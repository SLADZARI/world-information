**Структура 249 карточек:** 4 страны с предварительными, атрибутированными измерениями (**PL, GB, US, CN**); 3 страны стоят в очереди на предметное исследование (**BY, RU, UA**); остальные 242 имеют статус `unresearched`. **Не исследовано ≠ 0% интернет-пользователей**. Термин «страна / территория» относится к справочнику ISO-3166-1, а не к утверждению о суверенитете; отдельно учитывать геополитику, признание и границы.

### Страна открывается через URL

После локального открытия HTML допускается параметр `?country=PL` (`BY`, `US`, и т. д.). В интерфейсе есть поиск, фильтр готовности и раскрытие источников/методов. Это **локальная HTML-страница**, а не опубликованный сервис и не подключённая БД.

## Карточка цифровой среды (контракт)

`country_code`, `as_of`, `status`, `review_status`, `measurement_ids`, `source_ids`, `operators`, `platforms`, `social_groups`, `digital_rights`, `research_gaps`, `notes`.

**Поля в последующей версии должны раскрывать:**

1. Фиксированная и мобильная связь: покрытие, подключение, стоимость, качество, операторы, региональная концентрация — разные знаменатели.
2. Соцсети и мессенджеры: популярность **среди какой популяции**, новостное использование, языки, функции и возраст; не путать рекламную аудиторию с уникальными активными людьми.
3. Медиапотребление и офлайн-каналы: ТВ, радио, редакционные сайты, сетевые сообщества, опросы.
4. Реальные гражданские права и доступ: ограничения и доступность для граждан/резидентов/неграждан, законы и инциденты с датами; ни один показатель не представляет всё население.
5. Изменения поведения: **гипотезы отдельно от подтверждённых эффектов**. Общий «процент влияния диджитал» запрещён без указания контрфакта, исхода, дизайна, горизонта и неопределённости.

### Почему 249

Исходный список `Name,Code` закреплён за ревизией `datasets/country-list` `ca393dfa16db21ce07be77902c1c129d63c86d9f`, PDDL-1.0 от составителей, с **прямым предупреждением о возможных правах ISO на коммерческое использование**. Используется только минимальный справочник названия/код, источник указан в сгенерированном индексе. Для серий данных дополнительно сверять [UN Statistics Division M49](https://unstats.un.org/unsd/methodology/m49/). Не объявлять ISO-лицензионный вопрос закрытым. Выбор справочника не делает утверждений о политическом статусе территорий. Не включаем неофициальные пользовательские коды (`XK` и прочие) как ISO-3166-1.

## Как происходит пополнение — фактически реализованный процесс

**Добавить новое наблюдение:**

1. Найти и проверить первоисточник. Зафиксировать дату его публикации, обнаружения, охват, географию, группу, знаменатель, методику, единицу, ограничения, лицензию/права и данные сравнения. Не переносить числа из перепечаток как новые независимые измерения.
2. Добавить `source` и `measurement` в `data/research/digital-ecosystems/baseline-2026-10-31.json` либо создать новую датированную базу в следующей итерации миграции (текущий генератор читает существующую). **Не менять смысл исторической версии без явного следа ревизии**.
3. Создать или обновить `data/catalog/digital-countries/XX.json`; указать существующие `source_ids`, `measurement_ids`, пробелы исследования, `review_required`. Нельзя привязать показатель другой страны и нельзя записать долю оператора без документированной метрики с понятным охватом.
4. Выполнить `python tools/validate_digital_ecosystem.py`, затем `python tools/build_digital_country_catalog.py` и `python -m unittest discover -s tests -p 'test_digital_country_catalog.py'`.
5. В PR включить **исходную запись** + обновлённые сгенерированные `data/catalog/country-index.generated.json` и `prototype/digital-country-catalog.html`. CI выполняет `--check` и отклоняет несогласованную генерацию.
6. После ручной исследовательской и лицензионной проверки PR можно объединять; GitHub не должен автоматически объявлять новые данные подтверждёнными.

Профили могут дополняться **при следующих исследованиях** через PR. CI поддерживает корректность каталога **после добавления данных**, но **не выполняет самостоятельное научное исследование, не ходит в API и не перепроверяет публикации**. Для автоматических проверок новых исследований потребуется отдельный план источников/расписание и сервис отслеживания с квотами, лицензиями и дедупликацией.
